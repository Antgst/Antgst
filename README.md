# Développeur full-stack · SaaS · IA appliquée

Je conçois des applications web et des outils logiciels en partant d’un besoin concret : comprendre le problème, cadrer le produit, construire une solution maintenable, la tester et la livrer proprement.

Mon parcours précédent dans la grande distribution m’a apporté une forte culture opérationnelle, du management, de la priorisation et une attention particulière à la valeur métier. Aujourd’hui, je transpose cette expérience dans le développement logiciel, avec un intérêt marqué pour les **produits SaaS**, l’**automatisation** et les **agents IA**.

Je travaille principalement avec **React, Node.js, Express, PostgreSQL et Python**, tout en renforçant TypeScript, Docker, CI/CD et les architectures agentiques locales.

## Ce que je construis

### KERNO — Marketplace SaaS B2B

**React · Vite · Node.js · Express · PostgreSQL · Prisma · JWT · Tailwind CSS · Docker**

KERNO est un MVP de marketplace B2B conçu pour faciliter la découverte de fournisseurs, la visibilité de leurs produits et les premières demandes structurées entre magasins et fournisseurs.

Le projet couvre notamment :

- authentification et gestion des rôles ;
- profils magasins et fournisseurs ;
- catalogue produits et fournisseurs ;
- recherche et consultation des offres ;
- demandes de contact ou de devis ;
- API REST, PostgreSQL et Prisma ;
- tests, documentation et automatisation CI/CD.

[Voir le dépôt KERNO](https://github.com/Antgst/Kerno-MVP)

### Outils développeur, automatisation et agents IA

En parallèle des applications web, je travaille sur des outils personnels autour de :

- l’orchestration de workflows de développement assistés par IA ;
- l’exécution locale avec Ollama ;
- la mémoire durable et la reprise de missions ;
- les politiques de sécurité et les permissions explicites ;
- les sandboxes et les actions réversibles ;
- la standardisation des workflows Codex, Git et GitHub ;
- la qualification d’idées SaaS avant investissement en développement.

L’objectif est de rendre l’IA utile dans un vrai cycle d’ingénierie sans lui déléguer aveuglément les décisions sensibles.

## Ma façon de travailler

```text
Besoin métier
    ↓
Cadrage et hypothèses
    ↓
Architecture simple et explicite
    ↓
Implémentation incrémentale
    ↓
Tests et revue du diff
    ↓
CI / validation
    ↓
Déploiement et documentation
```

Je privilégie les changements petits et vérifiables, les sources de vérité explicites, les tests utiles, les PR relisibles et la documentation qui évite de refaire deux fois la même enquête.
